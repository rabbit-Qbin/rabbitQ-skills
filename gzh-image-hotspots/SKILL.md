# 公众号图片局部跳转

## 首次使用引导

用户只说想用这个 Skill，或表示不知道怎么开始时，先说明用途，再给出下面的简短引导。根据已有信息调整，不要要求用户重复提供。

> 我可以给图片上的指定区域加跳转链接，也可以把多张图拼成长图。最后给你一个 HTML，打开后点「一键复制到公众号」就能粘贴到草稿正文。
>
> 开始时发我三样东西。第一是原图或本地文件路径。第二是想让读者点哪里，用文字描述或发红框截图都行。第三是每个区域对应的链接，直接粘贴平台的分享链接即可。
>
> 例如「用这张图，右下角的购买按钮跳转到这条天猫分享链接」。如果有多个按钮，每行写一组「区域 → 链接」。如果要拼长图，再告诉我图片从上到下的顺序。希望 HTML 放在指定位置的话，也可以一并告诉我。

材料已齐时用一句话说明本次会生成什么，然后直接处理。材料不齐时只问尚缺的部分，多个缺项一次问清。用户不用测坐标、转换链接或制作配置文件。

## 确认材料

- 接受图片附件或本地文件路径。每个热区需要对应链接。位置可用文字描述，例如「点击购买按钮和整块商品介绍」，也可用红框、圈选、涂色的截图标注。优先根据图中文字、图标和标注主动识别。如果已经明确，直接处理。仅在原图、链接对应关系、热区范围或长图顺序无法判断时，合并询问缺失项。
- 一般用未标注的原图交付。标注截图可能有裁切、缩放、留白，先用共同视觉特征对齐到原图，按红线中心或圈选外接矩形落坐标。只有标注图且标记会影响成品时，请用户提供未标注原图。保留二维码和其他画面。
- 接受公开商品页、平台分享长链、短链或含链接的分享文案。提取网址时保留商品定位及必要查询参数。遇到微信 `mp/wapredirect`，脚本读取其 `url` 参数中的公开目标地址。按用户给出的目标绑定。实际在微信打开目标页需要草稿预览验证。

## 生成与交付

1. 识别原图尺寸，按各图 EXIF 显示方向量矩形，坐标为 `[左, 上, 右, 下]`，右和下取排他边界，热区不能重叠。用包内 [生成脚本](scripts/build_hotspots.py) 实际生成 HTML。按 [运行与参数](references/input.md) 检查 Python 和 Pillow，缺依赖时先处理依赖。由 AI 根据用户材料建立 JSON 并调用脚本，用户只需提供原图、位置和链接。
2. **单图**按坐标把原图无损切片，使用普通图片超链接包裹对应切片，再拼回原样。**长图**先按各自原图的坐标设置热区，再把处理后的片段与普通图片按给定顺序纵向排在同一个 HTML 模块里。各图按同一正文宽度展示，保持纵横比，整块可以一次复制。这样预览保留每张图的点击区域。
3. HTML 输出路径按以下顺序确定。用户指定文件路径或目录时，使用该位置。同一交付有现成的 HTML 时沿用原文件，除非用户指定换位置。新交付未指定路径时，默认放到用户所提供原图的文件夹。长图的所有原图位于同一个文件夹时也采用该默认值。只有附件临时路径、原图分布在多个目录或默认目录不可写，且没有明确输出位置时，和其他缺失材料一起询问用户。生成后先本地检查再覆盖已有入口。交付一个 HTML，告诉用户用 Chrome 或 Edge 打开（已打开则刷新）、点「一键复制到公众号」、粘贴到草稿正文。仅在用户另有要求时额外交付静态长图。
4. 核对产物路径、图序、链接和框外空白。有浏览器测试能力时，实际点击复制并粘贴到本地富文本区，在窄屏和桌面宽度核对图片与链接；能力不可用时完成可做的静态检查并说明。公众号端由用户保存、重开草稿后在手机微信逐个点击，区分图片保留、链接保留和目标页打开。社媒主页和平台商品分享短链已分别完成公众号实测。新排版及新链接按实际预览验收。
5. 失败时根据保存后的正文源码与手机提示判断是图片未落地、链接未保存还是目标站点打开失败。只提取正文结构，保护后台会话字段。旧试验中 SVG 底图被改写，SVG 内的链接也被清除。优先沿用已验证的普通图片切片结构。
